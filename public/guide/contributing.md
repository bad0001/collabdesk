# 贡献指南

欢迎改进通用协作能力、易用性、测试和文档。请保持平台边界：**共享信息与数据库，不内置模型调度，不自动代表用户操作外部服务**。

## 开始前

1. 先阅读 [快速开始](getting-started.md)、[API](api.md) 和 [安全说明](security.md)。
2. 使用自己的新本地数据库及合成成员、任务、短信；不连接任何真实用户实例。
3. 与维护者讨论影响身份/授权/数据库版本的变化，说明兼容与回退方案。
4. 此仓库许可证以最终根 `LICENSE` 为准；不要从部署说明或草稿推断授权条款。

## 代码约定

- Python后端/CLI优先标准库，新的依赖需说明必要性、许可证及运维成本。
- SwiftUI客户端保留简洁用户界面；不要让技术接口说明占据主操作页面。
- stable IDs用于关联，显示名可变；身份和作者来自服务端凭据。
- 写操作核对角色、当前任务归属、version及授权阶段；缺少/不可见对象不暴露他人资料。
- 普通操作幂等；单次秘密仅首次交接，不能把其响应正文复制到持久幂等回执。
- 验证码RAM-only，事务失败同时恢复数据库和RAM状态，消费/过期/转派/重启清理；不在日志/断言输出真实码。
- 公开watch保持最小字段、不透明游标，成员无关更新/心跳不制造无意义唤醒。
- 业务正文/AI发言视为不可信数据，不能直接拼成shell命令或系统指令。

## 测试

从根目录：

```sh
python3 -B -m unittest discover -s backend -p 'test_*.py'
python3 -B -m unittest discover -s clients -p 'test_*.py'
```

Apple客户端使用当前 `ios/project.yml` 生成工程，在自己的模拟器运行unit/UI tests。真机/签名/推送/短信自动化另行验收，不能用模拟测试结果替代设备到达证据。

涉及权限/短期码，至少覆盖：正确成员、其他成员、Leader/admin差异、未知metadata、版本冲突、原子争用、过期、消费、正式授权待批/拒绝、任务交接/结束、重启和失败补偿。涉及增量，覆盖全量reset/upsert/delete、失效游标、跨origin/成员/工作区缓存拒绝。部署变化只操作自己隔离服务，不运行现场控制器。

## Pull request

描述问题、改动边界、接口/数据库兼容、实际运行的测试命令及结果。区分“代码已实现”“部署已执行”“手机已安装”“实际显示/自动入库已验收”。未运行的测试明确写未运行。

提交前检查diff及新增文件。不提交：`.secrets`、`.data`、数据库/备份、`.p8/.pem`、成员/设备Token、真实短信、个人签名设置、DerivedData、现场验证日志、机器/服务器专用发布包。文档用保留域和通用路径，不要把维护者个人环境写成默认部署。

安全问题先走 [私人报告流程](security.md)，不要把敏感细节放普通issue/PR。
